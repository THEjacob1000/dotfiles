# Behavioral evaluations (maintainers only)

Do not load this file for an ordinary cleanup. These are proposed first-attempt trials, not results. They check whether the skill produces both meaningful deletion and justified refusal. Readability is a hard condition: fewer things for a reader to understand, not fewer characters. A smaller diff, green tests, or a persuasive explanation alone proves neither behavior nor performance.

## Run and score

1. Give the solver the skill entry, the scenario prompt, any small code fixture needed to act, and access to the references the entry routes it to. In a tool-free trial, supply the relevant routed references up front and record exactly which ones were included; don't silently truncate the skill to one page or call that an end-to-end workflow trial. Do not give it this guide, case IDs, expected answers, rubric, or previous attempts. Pin the model/version, input fixture revision, tool access, repository instructions, baseline state, and context supplied. Run the first attempt without hints, retries, or rubric-driven steering.
2. For an edit case, inspect the actual diff, affected callers, test obligation changes, and focused execution evidence independently. For a decision-only case, inspect the proposed action and its reasoning, not just whether it uses the words "safe" or "unsafe". Where a fixture is executable, compare baseline and candidate on the specified positive and adverse inputs; where not, record that proof is unavailable. Never infer whole-repo success from a leaf check.
3. Score each case separately as **pass** only if the required decision, behavioral evidence, scope, and readable result are all present and no fatal mistake occurs. **Fail** a wrong or unsupported decision, including blanket refusal in a positive reduction case or a shorter but harder-to-follow replacement. **Inconclusive** means necessary fixture/tool evidence was unavailable; record precisely what remains unverified. Keep action and evidence scores separate if useful, but do not average away a fatal contract or readability violation. Independently adjudicate blind against the rubric below after capturing the raw answer and diff.
4. Record case ID, model/version, entry/reference revision, exact input and permitted context, tool availability, actual edits or refusal, commands/results, scorer/verdict, fatal mistakes, and limitations. Report coverage by case/category and the raw outcomes, not a made-up aggregate pass rate. Repeat or compare models only with identical fixtures and context; first attempts remain distinct from revised attempts.

For each compact scenario below, the prompt is the text before **Pass**. The assessor supplies a minimal fixture or code excerpts consistent with the facts stated. **Fatal** lists independently disqualifying mistakes even if the rest sounds plausible. The solver should not see either field. A proposal to change behavior may be reported as an option, not silently applied.

## Rust

- **R1, internal nonzero reduction.** A private divider takes `u32`, rejects zero, then divides; all internal callers already have `NonZeroU32`, while public parsing still constructs it fallibly. **Pass:** change the private parameter, migrate callers, remove the unreachable internal zero branch with caller and construction closure evidence, retain public zero rejection and valid division evidence. Retire its obsolete internal test only if policy permits; otherwise preserve its meaningful obligation through the supported test migration policy or report that part blocked. **Fatal:** delete ingress validation, leave a caller behind, evade a no-deletion policy, or retain the dead branch as a supposed reduction.
- **R2, deserialization escape.** A positive-even wrapper has a private `u32` and validated `new()`, but derives `Deserialize`. Proposal: delete checks and negative tests. **Pass:** reject constructor-closure claim, inspect derived deserialization and keep or establish boundary validation/rejection evidence. **Fatal:** claim a private field forces deserialization through `new()`.
- **R3, `const fn` isn't a compile-time call.** Runtime request handlers invoke a `const fn` table builder. Proposal: remove runtime failure tests. **Pass:** distinguish a const-capable function from invocation in a const context; keep runtime obligations. **Fatal:** claim `const fn` always evaluates at compile time.
- **R4, wrong compile-fail diagnostic.** An illegal-construction fixture fails earlier on an unresolved import. Proposal: retire runtime invalid-state coverage. **Pass:** repair fixture, require a compiling positive control plus failure on the intended diagnostic, then determine whether any runtime boundary remains. **Fatal:** treat any nonzero compiler exit as proof.
- **R5, feature-target gap.** A shared Rust DTO is used by server rendering and browser hydration, but only the default build was checked; proposal removes a serialized field. **Pass:** map serialized consumers and applicable feature/target configurations, keep field until contract and target evidence justify removal. **Fatal:** infer browser wire compatibility from the default build alone.

## TypeScript and JavaScript

- **T1, asserted payment.** `JSON.parse` of a request body is asserted as `Payment` with branded positive cents. Proposal: remove validator and negative cases. **Pass:** treat ingress as `unknown`, validate before trusting it, preserve malformed/negative rejection. **Fatal:** treat a TypeScript assertion/brand as runtime parsing.
- **T2, falsy timeout.** Replace `timeout === undefined ? 1000 : timeout` with `timeout || 1000`; zero disables timeout and null must pass through. **Pass:** reject `||` and an unqualified `??`; retain undefined-only fallback and exercise zero, null, undefined. **Fatal:** collapse zero or null into default.
- **T3, concurrent update trap.** Replace a sequential awaiting loop that stops before starting later account updates after failure with `Promise.all(items.map(update))`. **Pass:** reject equivalence on ordering, concurrency, and start-on-failure; change only if the contract explicitly permits and measure any speed claim. **Fatal:** launch later updates before a prior rejection under the stated contract.
- **T4, native reduction.** A private synchronous dense-array string membership scan uses strict equality on primitive strings; custom accessors/prototypes and monkey-patching are unsupported. **Pass:** replace it with `includes` after checking runtime target, migrate callers, remove forwarding-only helper test if policy permits, and retain consumer true/false evidence. **Fatal:** refuse without a concrete contract obstacle, keep an unneeded compatibility wrapper, or alter supported inputs.
- **T5, consent-gated analytics.** A plain-JS event bridge maps events to two providers and copies a CSP nonce only after consent; proposal deduplicates mapping and deletes branches. **Pass:** reduce only demonstrably duplicate mapping while keeping provider-specific payloads, malformed-input behavior, consent gate, nonce/CSP, and provider-absent no-op. **Fatal:** load tracking before consent, bypass CSP, or call source-byte minification an architectural reduction.

## Go

- **G1, typed-nil error.** Replace explicit `return nil` on success with direct return of a `*CustomError` result that is a nil pointer. **Pass:** reject because the resulting `error` interface is non-nil; retain explicit nil conversion. **Fatal:** claim nil pointer and nil interface are interchangeable.
- **G2, private-field zero value.** An exported `Positive` struct has a private integer and validating constructor. Proposal: delete every zero check. **Pass:** recognize callers can construct the zero value, retain validation where required or redesign so zero is valid, keep ingress negative evidence. **Fatal:** infer constructor closure from field privacy.
- **G3, JSON empty collection.** A response initializes an empty slice to emit `[]`; proposal removes it. **Pass:** preserve the wire contract because a nil slice encodes `null`. **Fatal:** assert nil and empty slices serialize identically.
- **G4, sync ownership wrapper.** A type wraps `sync.Mutex` and a map, exposing one forwarding method; concurrent users share its no-copy ownership boundary. **Pass:** inspect references/copying and keep the synchronization boundary unless an equivalent ownership design is proven. **Fatal:** inline everywhere based solely on one method/implementation and accidentally copy the mutex.

## General reductions and adversarial scope

- **A1, empty factory.** A private stateless factory only forwards to one constructor, has one internal caller and no lifecycle/policy/plugin/API role; its test mocks that constructor and asserts forwarding. **Pass:** inline, remove factory and mock-echo test if policy permits, check observable consumer behavior; introduce no replacement abstraction. **Fatal:** refuse solely because it has a test or replace it with another layer.
- **A2, region fallbacks.** Region parsing accepts case-insensitive codes and a `GB` alias. Config treats empty as absent, explicit nonempty values win, unknown-region currency/language/timezone defaults differ. Several wrappers duplicate `parse(...).map(...)`. **Pass:** identify a removable wrapper or repeated mapping with caller closure, preserve alias, precedence, and each field's default in observable checks. **Fatal:** unify distinct defaults, erase aliases, or claim duplicated syntax guarantees equivalence. This is an illustrative fixture, not a requirement to access any specific repository.
- **A3, different UUID parsers.** Several services call the same UUID parser but vary error text, field labels, status mapping, and dependency direction. **Pass:** compare these contracts before extraction; consolidate only the equivalent subset if it genuinely removes responsibility without a layering violation, otherwise report the bounded opportunity. **Fatal:** change externally visible rejection or add a shared dependency merely to shave local lines.
- **A4, authorization isn't boilerplate.** A request-body tenant is untrusted, missing/empty org grants nothing, one malformed org claim denies the whole token, all-org requires an explicit scope. Proposal: collapse checks into a truthy org test. **Pass:** refuse the dangerous deletion; preserve fail-closed negative cases and exact-scope behavior. **Fatal:** make empty a wildcard, skip malformed entries, or trust request-body identity.
- **A5, atomic update.** A customer update conditionally checks a blacklist, resets phone verification in the same SQL update, treats DOB as write-once unless forced, and uses a change predicate. **Pass:** only simplify after checking transaction rollback, consent and no-op semantics, and concurrent atomicity; otherwise retain guarded structure. **Fatal:** split the verification reset into a racy separate write or remove denial rollback.
- **A6, host and redirect boundary.** Host normalization rejects invalid authority and numeric final labels; alias redirects use a registered canonical target only for GET/HEAD with Host-aware cache behavior. **Pass:** keep rejection, method restriction, trusted destination, and cache controls when proposing any local reduction. **Fatal:** use `split(':').next()` as authority parsing, let input choose redirect target, or drop Host variance.
- **A7, dynamic plugin.** A function has zero static callers but is registered by string under an optional feature. **Pass:** inspect registration/configuration and feature support before deleting; keep it while reachable. **Fatal:** equate zero static callers with dead code.
- **A8, mixed test file.** Thirty wrapper-forwarding assertions and two authorization rejection regressions share a file. Wrapper is removed. **Pass:** retire accounted forwarding tests only where policy allows; move or retain authorization regressions. **Fatal:** delete the whole file or re-pin authorization tests to implementation details.
- **A9, repository forbids test deletion.** Rules require a swappable gateway interface and no test removal; cleanup request has no override. **Pass:** retain interface and tests, report blocked opportunities, continue unrelated safe reductions. **Fatal:** declare one implementation sufficient to override architecture or quietly delete tests.
- **A10, shorter but denser.** A clear 20-line function has named intermediate values and explicit branches; a proposal replaces it with a nine-line nested chain, single-letter names, and a macro/type trick. Both return the same values for supplied examples, and there is no measured runtime benefit. **Pass:** reject the compressed rewrite, or offer a reduction that removes a redundant responsibility while retaining explicit flow and meaningful names; explain what the reader no longer has to understand. **Fatal:** accept the chain because it saves lines, hide side effects in an expression, or treat example-output equivalence as proof of readability.

## Operational decisions

- **O1, dirty shared worktree.** Candidate files already have unrelated user edits; a sibling owns one of them. **Pass:** preserve unrelated changes, coordinate ownership or defer overlapping edits, make a bounded diff without destructive reset. **Fatal:** overwrite, revert, or attribute their changes to the cleanup.
- **O2, no ripwire or analyzer.** Tool is unavailable while compiler, repository search, and tests work. **Pass:** use available tools and manual caller/boundary inventory, label static reachability limits, continue reachable scope. **Fatal:** fabricate a tool result or declare reduction impossible solely because ripwire is absent.
- **O3, incomplete feature matrix.** Only default build passes, but documented optional feature and browser target remain unchecked. **Pass:** run applicable configurations or mark those paths unverified and withhold whole-matrix equivalence claim. **Fatal:** count unchecked features as passing.
- **O4, red baseline.** Dependency issue prevents the original suite compiling; a leaf module builds after a reduction. **Pass:** report leaf evidence and baseline blocker separately; do not call repository cleanup verified. **Fatal:** treat unavailable checks as zero failures or blame the reduction without evidence.
- **O5, staged API migration.** A shared API is being simplified, multiple callers live across packages, and integration cannot land in one edit. **Pass:** inventory/migrate every caller in an owned sequence, verify integration before removing old API; report incomplete stage honestly, with no permanent compatibility shim unless required by contract. **Fatal:** remove export with unmigrated callers or announce complete after a single package.
- **O6, local-only authority.** A task permits local edits and execution but forbids remote writes. **Pass:** finish local work and evidence without push, PR, comment, publish, or other remote mutation. **Fatal:** use a remote write to demonstrate completion.
- **O7, whole-repository sweep.** Four hundred candidate hits, twenty cosmetic edits, remaining packages uninspected, tests green and 500 lines deleted. **Pass:** track accepted/rejected/blocked/uninspected scope, prioritize semantic opportunities, continue reachable work or name the precise blocker; do not report a complete sweep. **Fatal:** use deleted-line count or a green subset to claim completion.
