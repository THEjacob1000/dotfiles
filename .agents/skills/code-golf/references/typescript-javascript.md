# TypeScript and JavaScript reductions

Use this catalog for both `.ts` and plain `.js`. Readability is a hard acceptance condition: reject a shorter rewrite if it makes the reader track more implicit state, operators, callbacks, types or indirection. A longer clear loop beats a compressed `reduce` chain or clever type trick. Delete states, duplicated policy, ownership transitions and unnecessary runtime work while preserving values, errors, property shape, evaluation order, identity, side effects, scheduling and supported environments. For evidence and test retirement, use [proof and tests](proof-and-tests.md); this page lists language-specific hazards.

## Types describe a checked program, not its runtime inputs

Type annotations, `as T`, `!`, `satisfies`, and `import type` do not validate values at runtime. `any`, unchecked JavaScript callers, declaration files, casts, JSON, storage, environment variables, network payloads, plugins and `postMessage` can violate the type. Keep one validation/normalization point where data crosses into a trusted internal representation, then remove *duplicate* checks downstream only if all entry paths pass through it. Retain checks at separately callable public boundaries. In JS-only projects, use actual runtime checks; JSDoc/`checkJs` can improve static feedback but still cannot validate input. `strict` is a family of static checks, not a proof of runtime validity; inspect effective compiler options, especially `strictNullChecks`, `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`, before removing a guard. `satisfies` (TS 4.9+) checks assignability of an expression while retaining inference, not the shape of deserialized data. [TS everyday types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html), [narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html), [satisfies](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-9.html), [TSConfig](https://www.typescriptlang.org/tsconfig/)

| Reduction | Before -> after | Apply when; refuse when | Proof / test disposition |
| --- | --- | --- | --- |
| One runtime source of truth | `const states = ["idle", "busy"] as const; type State = "idle" \| "busy"` -> `const states = ["idle", "busy"] as const; type State = (typeof states)[number]` | The values are already needed at runtime. Do not add a runtime array just to save a type declaration, or mistake the derived type for membership validation. JS can reuse the same `states` in checks without a type alias. | Compile type consumers; exercise the membership check at the input boundary, including unknown values. |
| One discriminant, one branch | `if (r.ok) handle(r.value); else if (!r.ok) fail(r.error)` -> `if (r.ok) handle(r.value); else fail(r.error)` for `type Result = {ok: true; value: T} \| {ok: false; error: Error}` | Trusted, closed union with disjoint literal tags and no mutation between branches. Do not drop a malformed-tag error for externally supplied objects or widen `ok` to `boolean`; in JS the same branch reduction needs runtime invariant proof. | Compile every variant; test malformed input at its validator, retain a boundary failure test if that is an observable contract. |
| Delete rechecks after validation | `const parsed = parsePayload(raw); if (typeof parsed.id !== "string") throw ...; consume(parsed.id)` -> `const parsed = parsePayload(raw); consume(parsed.id)` | `parsePayload` actually checks `id` on *all* success paths, not `JSON.parse(raw) as Payload`, and cannot yield a mutable object whose `id` is changed between steps. | Positive and negative parser cases stay; retire only the redundant downstream check's test, not invalid-input coverage. |
| Infer without duplicating models | `function loadRows() { return [{id: "a", score: 1}]; }` plus a separately copied `type Row = {id: string; score: number}` -> keep the producer and use `type Row = ReturnType<typeof loadRows>[number]` for an internal consumer. For an async producer, use `Awaited<ReturnType<typeof loadRows>>[number]`. | The producer owns the shape and has no `Row` return annotation, avoiding a circular type. Keep explicit exported types for stable API contracts or when inference widens literals/turns incidental implementation into API. `typeof`, indexed access, `keyof`, and `ReturnType` replace *duplicated* shapes, not every named type. | Compile external consumers/declarations; check public API compatibility rather than raw line count. |

`as const` can preserve literal tuples for derived types, but doesn't freeze objects at runtime. `satisfies` can replace a broad annotation when preserving precise property inference matters, e.g. `const labels = {idle: "Idle", busy: "Busy"} satisfies Record<State, string>`; it cannot replace the runtime check for `State` coming from JSON. [TS typeof type operator](https://www.typescriptlang.org/docs/handbook/2/typeof-types.html), [indexed access](https://www.typescriptlang.org/docs/handbook/2/indexed-access-types.html), [const assertions](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-4.html)

## Remove wrappers and duplicate state, not boundaries

- Replace `const isReady = () => service.isReady()` with the direct call when the wrapper adds no policy, adaptation, injectable seam, instrumentation, identity or public API and all callers can migrate. Beware method extraction: `const f = service.isReady; f()` can lose `this`; invoke `service.isReady()`.
- Collapse duplicate options/factories if every caller passes the same values and the factory has no lifecycle, allocation policy, lazy behavior, subclass hook or swappable contract. A per-request factory returning fresh mutable objects cannot be replaced by a shared singleton. A default option may differ from an explicit `undefined`, especially across spreads and serializers.
- Compute derived values from their authoritative state rather than maintaining a second synchronized field. In UI code, render-time derivation can replace an effect whose only job is copying a prop/store value; keep effects for subscriptions, timers, network calls, DOM synchronization and cleanup. Do not call expensive or side-effectful calculations on every render without checking the existing lifecycle. This is a state-ownership rule, not a framework-specific recipe. [React: you might not need an effect](https://react.dev/learn/you-might-not-need-an-effect)
- Prefer existing standard APIs and already-installed project libraries over local reimplementations, after comparing exact semantics. `URL`/`URLSearchParams`, `Set`, `Map`, `Object.hasOwn`, `Array.prototype.find`, `Intl`, `TextEncoder`, platform `fetch`/`AbortController` are candidates, not interchangeable substitutes for encoding rules, validation, order, or compatibility. Do not add a dependency to delete a six-line local function without a real maintenance win. [MDN built-ins](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects), [Web APIs](https://developer.mozilla.org/en-US/docs/Web/API)

## Expressions that silently change contracts

| Proposed shortcut | Refuse or prove |
| --- | --- |
| `x || fallback` -> `x ?? fallback` | `||` replaces `0`, `false`, `""` and `NaN`; `??` replaces only `null`/`undefined`. Keep the exact intended domain. `x?.y` only short-circuits a nullish base, not a missing/invalid `y`. [Nullish coalescing](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Nullish_coalescing), [optional chaining](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Optional_chaining) |
| `"key" in obj` -> `Object.hasOwn(obj, "key")` or `obj.key !== undefined` | `in` includes inherited properties; `hasOwn` does not; reading cannot distinguish absent from present-with-`undefined` and may invoke a getter. Prototype-free maps and inherited configuration are different contracts. Test absent, own-undefined and inherited cases if relevant. [Object.hasOwn](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/hasOwn), [`in`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/in) |
| `a === b` -> `Object.is(a, b)` or JSON/string comparison | `Object.is` distinguishes `+0`/`-0` and equates `NaN`; `===` does the reverse for those cases. Object equality by either is identity, not structure. JSON may discard `undefined`, reorder interpretation and invoke `toJSON`; do not invent deep equality to save a comparator. [Equality](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Equality_comparisons_and_sameness) |
| Loop -> `map`/`filter`/`reduce`, or `filter(Boolean)` | `map` allocates an output and skips holes; `filter` removes holes and changes indexes; `for...of` visits holes as `undefined`. `filter(Boolean)` also drops valid falsy values. Keep a boring loop when it preserves one-pass mutation, early exit or clarity; don't claim a performance win without measurement. `array.map(parseInt)` passes the index as radix. [Array.map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/map), [Array.filter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/filter), [for...of](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for...of) |
| `Object.entries(obj)`/spread to replace property logic | Enumeration sees own enumerable properties, not symbols in `Object.entries`, inherited properties or nonenumerables. Object spread copies own enumerable values, invokes getters, makes plain data properties and is shallow. Object insertion order has integer-key ordering rules; sorting without a comparator is lexicographic and mutates the array. Check prototypes, getters, symbols, sparse arrays and ordering before shortening. [Object.entries](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/entries), [spread](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Spread_syntax), [Array.sort](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort) |
| `items = [...items, next]` -> `items.push(next)` | Same apparent contents, different identity and mutation visible to aliases, memoization, frozen inputs or callers. Conversely replacing mutation with copy can lose shared-state updates; spread is shallow. [Spread](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Spread_syntax) |

Concrete safe JS reduction: `const found = items.filter(x => x.id === id)[0]` -> `const found = items.find(x => x.id === id)` when a match's value may be returned directly, no caller needs a filtered array, and the callback is pure or later callback invocations were unobservable. `filter` skips empty slots but `find` visits them as `undefined`, so refuse on sparse inputs unless the predicate tolerates that; retain coverage for first match, no match and sparse arrays where supported. `find` also stops at the first match, changing later side effects. [Array.find](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/find), [Array.filter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/filter)

## Async work, errors and lifetime

- `return await promise` -> `return promise` is sometimes safe inside an `async` function, but *not* in a `try/catch` intended to catch rejection, or where `finally` must run after settlement. `async` already returns a promise; compare rejection timing, stack traces and cleanup before removing `await`. `throw err` -> `return err` changes a rejection into a fulfillment. Preserve error type/cause/message where public consumers rely on them; don't blanket-catch and return `undefined` to shrink error handling. [async function](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function), [try/finally](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch)
- `const a = await first(); const b = await second();` -> `const [a, b] = await Promise.all([first(), second()])` only for independent operations when concurrent start, failure selection and partial side effects are acceptable. `Promise.all` preserves result position but rejects on first rejection and does not cancel unfinished work. Conversely `await Promise.all(items.map(save))` -> sequential `for...of` only if serialization is required; don't accidentally remove concurrency or backpressure. Exercise success, first failure, late failure and ordering when they matter. [Promise.all](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/all)
- Delete a local abort/timer/subscription wrapper only when the existing owner already propagates an `AbortSignal` and disposes all acquired resources on success, failure and cancellation. Removing an effect cleanup, `finally`, `removeEventListener`, `clearTimeout`, stream close or controller abort because the happy path finishes is not golf. `Promise.race` with a timeout does not itself cancel the losing operation. [AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController), [AbortSignal](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal), [Promise.race](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/race)

## Modules and supported runtimes

An apparently unused export may be reached by a package `exports` map, consumers outside the repository, dynamic `import()`, reflection, plugin registration or side-effect imports. Resolve those contracts before deleting an exported symbol, barrel or module. Tree-shaking is build-tool dependent and side-effect sensitive; deleting a re-export is not proof its implementation disappears from the shipped bundle. Check actual emitted artifacts when bundle size is the goal. Type-only imports erase; value imports and top-level evaluation can matter. [TS modules](https://www.typescriptlang.org/docs/handbook/2/modules.html), [MDN modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules), [Node packages exports](https://nodejs.org/api/packages.html#package-entry-points)

Before replacing a ponyfill with `Object.hasOwn`, `structuredClone`, `Array.prototype.at`, `toSorted`, `fetch`, `AbortSignal.timeout` or `Promise.withResolvers`, check the project's *oldest* supported Node/browser/worker runtime, test harness, transpilation target, `lib` declarations and polyfill strategy. TypeScript's `target` and `lib` control emit and available declarations, not universal runtime availability; a successful typecheck does not install a built-in. Preserve semantics as well as availability (`structuredClone` is not an arbitrary object copier). [TS target](https://www.typescriptlang.org/tsconfig/#target), [TS lib](https://www.typescriptlang.org/tsconfig/#lib), [structured clone](https://developer.mozilla.org/en-US/docs/Web/API/Window/structuredClone), [Node globals](https://nodejs.org/api/globals.html)

## Agent anti-patterns to reject

No `as unknown as T` to silence a contract mismatch; no optional chaining everywhere to hide broken invariants; no `catch { return [] }` to turn errors into empty success; no replacing a validated parser with a cast; no duplicate schema/type/value registry that can drift; no universal `useMemo`/memoizer/cache for cheap derived values; no configurable factory for a single stable choice; no new `Result`/event bus/adapter layer that merely forwards a library API; no deletion based solely on a static search, typecheck, bundle warning or passing happy-path tests. Require one concrete owner and evidence for every removed responsibility.
