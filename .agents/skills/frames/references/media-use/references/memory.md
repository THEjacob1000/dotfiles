# User memory — preferences and recipes

Use `frames.media_prefs` and `frames.media_recipe` for the local two-tier stores. Both take `project`; `media_home` optionally selects a personal home containing `.media` (use a temporary home for tests).

## Preferences — remembered defaults

The lightweight tier of user memory: confirmed brief answers (destination, aspect, language, flow, storyboard, voice, style preset) persisted on the same two-tier split as assets — project `.media/preferences.json` (committed, the team inherits it) and personal `~/.media/preferences.json`. A value earns the personal tier by being confirmed in **two different projects**, so a one-off choice never pollutes the global defaults.

- **Get:** `frames.media_prefs {"project": "/absolute/path/to/project", "action": "get"}` merges personal and project entries, with project values winning and source receipts preserved.
- **Record:** `frames.media_prefs {"project": "/absolute/path/to/project", "action": "record", "key": "destination", "value": "x-feed"}` records a confirmed value. For `style_preset`, pass `"workflow": "frames references/faceless-explainer.md"`; the key is `style_preset.<workflow>`. The same value confirmed in two distinct project names promotes to the personal tier.

Only what the user actually confirmed gets recorded — never an inferred or defaulted value. How workflows consume these (a remembered value becomes the recommended default with a receipt, and never skips a question) is the brief contract's rule: `frames/references/brief-contract.md` § 2, Remembered defaults.

## Recipes — frozen video bundles

The heavyweight tier of user memory: one approved run frozen as a named, versioned bundle — `frame.md`, the storyboard skeleton (structure kept, content blanked to per-frame fill-ins), the brief skeleton (from `BRIEF.md` when the project has one — reusable frontmatter kept, run-shape and prose blanked), and the confirmed brief values. Same two tiers: project `.media/recipes/<name>/` (committed) and `~/.media/recipes/<name>/` (a freeze is already a confirmed bundle, so it promotes immediately — no two-project rule). Re-freezing a name bumps `version` and archives the old folder as `<name>@v<N>`.

- **Freeze:** `frames.media_recipe {"project": "/absolute/path/to/project", "action": "freeze", "name": "product-demo", "blocks": ["hero"]}` freezes the approved design and content-blanked storyboard/brief skeletons, appends inventory, archives older versions, and promotes locally. `BRIEF.md` decides workflow; `"workflow"` is only a fallback for a briefless project.
- **List:** `frames.media_recipe {"project": "/absolute/path/to/project", "action": "list", "workflow": "frames references/product-launch-video.md"}` merges both tiers, project-first, newest approval first.
- **Use:** `frames.media_recipe {"project": "/absolute/path/to/project", "action": "use", "name": "product-demo"}` imports a personal recipe when needed, copies its `frame.md` over the project's, and returns brief values plus skeleton paths. It does not overwrite `STORYBOARD.md` or `BRIEF.md`.

The freeze is offered once after the final approval (`frames/references/review-loop.md` § 4), and the intent layer (`/frames` → `references/intent-interview.md`, step 1) checks for a match before its first question. Adopting a recipe fills the brief, the design spec, and the storyboard skeleton — and unlike preferences it may skip the questions it answers: the bundle was approved as a whole, and adoption itself is the question.

## Files

- `.media/manifest.jsonl`: machine SSOT, one JSON record per line. Records are keyed by path and only appended, so
  the last record for a path is the file's record; a file moved or replaced by hand keeps (or loses) its record by path.
- `.media/index.md`: agent-readable table (id, type, dur, dims, path, description), regenerated by `frames.media_index {"project": "/absolute/path/to/project"}` from the append-only manifest's current records. Pass a typed `"record"` to append supplied local asset metadata before regeneration.
- `.media/preferences.json`: the project's remembered defaults (committed)
- `~/.media/`: global cross-project reuse cache (content-addressed, SHA-256)
- `~/.media/preferences.json`: personal remembered defaults (promoted after two projects)
- `.media/recipes/<name>/`: frozen video bundles — recipe.json + frame.md + storyboard skeleton (committed)
- `~/.media/recipes/<name>/`: personal recipe tier (promoted on freeze)
- `~/.media/misses.jsonl`: local-only resolve misses (asset resolution is not available in Numen, so nothing writes it)
