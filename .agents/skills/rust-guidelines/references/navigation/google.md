# Google Rust Style Guide

Google's [Rust Style Guide](https://google.github.io/styleguide/rustguide.html) is the primary style and API reference. The [local copy](../google/rustguide.md) is pinned and unmodified; read the sections below, not the whole document. Links use the explicit `<a id="...">` anchors in that source. Its [manifest](../google/upstream.json) records the revision and hashes; the accompanying [license](../google/LICENSE) is CC BY 3.0.

## Apply the right scope

Read [API design context](../google-sections/api-design-context.md#api-design-context) when deciding between a reusable library API and application code. Library means intended for other projects, not merely a Cargo `lib` target. Application APIs favour simplicity; library API rules are binding unless a local override applies.

Rules labelled Chrome, Android, Fuchsia or google3 apply only in those environments. In particular, Chromium's crate layout, import macro, async and thread restrictions, Fuchsia's mutex and the named test frameworks are not general Rust requirements. Use the repository's toolchain, formatter, runtime and tests. This guide does not authorize changing them, adding unstable features or suppressing a lint to pass checks.

## Resolve overlapping guidance

Google controls conflicts with the supplementary Microsoft and community sources. For example, its glob-import exceptions remain exceptions despite `M-NO-GLOB-REEXPORTS`; standard trait implementations take priority over `M-ESSENTIAL-FN-INHERENT`; and its naming guidance controls conflicts with `M-SHORT-NAMES`. Do not turn a qualified preference into an absolute ban: preserve the guide's library/application distinction and stated exceptions.

Local policy overrides Google's default `#[non_exhaustive]` advice for both enums and structs, and its permission to panic on nonfatal operational failures in developer-facing binaries. Do not remove existing attributes or change established API contracts merely to apply this skill. Dependency-owned non-exhaustive enums still require a wildcard; list the known variants when they have meaningful handling and make the unknown case safe.
